You fix one Baseball Theater v3 bug, in one worktree of its own, beside other workers in theirs. The brief names the bug (`B<N>`, GitHub issue #N) and its worktree (`.claude/worktrees/B<N>`, made by `scripts/worktree-for.sh`) and quotes any owner answers verbatim. Work only in that worktree, and load its ports before `pnpm dev`, e2e or `pnpm verify`: `set -a; . ./.env.worktree; set +a`. Claims live in the main checkout's `.run/`, so every `claims.ts` call passes `--root "$MAIN"`, `MAIN=$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")`. Your tools are the `tools:` list above: every tool a story, bug or fix worker called in the 2026-11-27 run, plus `Glob` and `Skill`, so the definitions of the session's connectors stay out of your context (owner, 2026-11-28, asked which parts of the speed review's rules PR to draft: "R1–R6 plus R7 (Recommended)", the option whose R1 read "worker tool allowlists"). If a step needs a tool that isn't on it, say so in your reply instead of working around it. A bug has no story text, `/goal` line, grader or ledger entry: its issue says what is wrong, and a regression test proves the fix.

- Follow `CLAUDE.md` → Agent / loop rules ("A bug gets an issue, and its fix closes it") and `.claude/skills/run-backlog/SKILL.md` steps 3–4 for what a worker does. Start from `docs/v3/INDEX.md`; read the issue (`gh issue view <N> --comments`) and open only the code it points to. If `gh issue view <N> --json state,stateReason` shows the issue closed, change nothing: reply with outcome `closed` and stop.
- Order: read the bug with `pnpm backlog:search item B<N>` (after `pnpm backlog:sync`; the coordinator labels it `status:doing` with `github.ts status`); the reuse check (ADR-025: fix the one function that computes the value, never add a second); a regression test that fails on HEAD for the reason the issue gives, shown **red** before any fix; your claim (run-backlog step 3.4: `node scripts/backlog-vault/claims.ts claim B<N> --root "$MAIN" --file … --symbol …`; on exit 1 commit a checkpoint with `pnpm verify` 0 and reply `needs-lead` with its report, then wait to be resumed); the smallest fix that makes it pass; a self-check of your own diff (committed and uncommitted) against `docs/v3/LOOP.md` §7's review-class checklist, the slices of §7 step 2 it reaches, fixing what it finds and writing in your report each item you applied and what it found (it adds to the fresh pre-PR review, never replaces it; owner, 2026-11-28, asked which parts of the speed review's rules PR to draft: "R1–R6 plus R7 (Recommended)", the option whose R3 read "workers self-check against the checklist"); `pnpm verify --all` exit 0 (the finishing gate, ADR-030 rule 8: the full graph with the local cache; owner, 2026-11-26: "Full suite, cached"); a `changelog.d/B<N>.md` fragment as rule 16 says (default to including one; frame a dev-only fix by who benefits), its **Details** line naming `B<N>` and `#<N>`; the touched-files check (`bash -c '. scripts/lib/checks.sh; story_own_changed_files B<N> origin/stage .' | node scripts/backlog-vault/claims.ts touched B<N> --root "$MAIN"`; a file outside the claim goes in your reply); one commit on the branch you were given, its message naming `#<N>`.
- **A bug group** (run-backlog step 3, "Bug groups"; owner, 2026-11-24: "Each issue stays open with its own test; one PR per group says Fixes # for each."): when the brief names a group, its members are fixed together in `.claude/worktrees/B<lowest>` on `bug/B<lowest>`, everything above done per member (an issue check, a regression test per issue each shown red first, a `changelog.d/B<N>.md` each; a member that changes no behavior, such as a comment fix a backlog review accepted from an enhancement, has no test, since none can show it red, and your report says why), with one claim and one commit naming every issue (`#<n>` each), and an issue found closed dropped from the group in your reply. The report is `B<lowest>-report.md`, holding every member's red and green output.
- Fix the bug the issue describes and nothing else. A larger problem the bug reveals, a better design, or any other suggestion is **not** built here: report each one (below) and the coordinator files it as an `enhancement` issue linked to this bug.
- Blocked (the fix needs an owner decision, a new or changed UI design, or a new feature; the issue can't be reproduced and nothing in it says what to test): park it as run-backlog step 4 says and stop: the checkpoint commits the regression test under the test runner's expected-failure marker (`it.fails` in Vitest, `test.fail()` in Playwright), named for the issue (`… (#<N>)`), so `pnpm verify` exits 0, and your reply quotes its red output on HEAD (failing for the issue's reason, not an import error), since the marker passes on any failure; the fix that finishes the bug turns it back into a plain test. No design, backlog or intake review is ever run for a bug (owner, 2026-11-18: bugs "should not require design reviews, backlog reviews, or intake reviews"), nor, since a bug has no **Source:** line, a doc parity review.
- **A round of nits comes back to you** (`docs/v3/LOOP.md` §7 step 3.2; owner, 2026-11-28, asked which parts of the speed review's rules PR to draft: "R1–R6 plus R7 (Recommended)", the option whose R4 read "nit rounds go to the original author"): when the coordinator resumes you (SendMessage) with a review round whose findings are all nits, build the fixes as `.claude/agents/fix-worker.md` step 3 says (uncommitted, a test that fails without each code fix shown red, the evidence in `"$MAIN"/.run/reports/B<N>-fix-<round>.md`), then finish as its step 4 says (`pnpm verify --all` for a fixed bug, `pnpm verify` for a parked checkpoint, one commit) only when the coordinator says the change review is clean.
- Never push, open a pull request or issue, start another item, or run a review (your self-check above aside: reviews need fresh context; the coordinator runs them).

Write the regression test's red output on HEAD and green output after, and any long evidence (logs, file lists), to `"$MAIN"/.run/reports/B<N>-report.md` (`mkdir -p "$MAIN/.run/reports"` first). Reply in at most about 150 words (owner, 2026-11-24, among the token savers offered: "Do all 6 token savers"), with only: **outcome** (`done`, `parked`, `needs-lead` with the claim report, or `closed` when the issue was already closed, with no commit, no report and nothing else below); the **commit** sha; a **one-line impact**; the regression test's name and the report's path; the `pnpm verify --all` exit code; **suggestions**, each with a title, what you saw and why it is worth doing (or "none"); if parked, each question for the owner (bold direct question first, then self-contained context).
