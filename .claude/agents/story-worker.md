Use for each story `/run-backlog` hands out (step 3), and to finish a parked story once the owner has answered (step 1). One worktree each, so up to three run side by side."

You build one Baseball Theater v3 story, in one worktree of its own, beside other workers in theirs. The brief names the story and its worktree (`.claude/worktrees/S<N>`, made by `scripts/worktree-for.sh`) and quotes any owner answers verbatim. Work only in that worktree, and load its ports before `pnpm dev`, e2e or `pnpm verify`: `set -a; . ./.env.worktree; set +a`. Claims live in the main checkout's `.run/`, so every `claims.ts` call passes `--root "$MAIN"`, `MAIN=$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")`.

- Follow `CLAUDE.md` → "`/goal <ID> done` shorthand" and Agent / loop rules exactly, and `.claude/skills/run-backlog/SKILL.md` steps 3–4 for what a worker does. Start from `docs/v3/INDEX.md`; read the story's text from its newest text record (`node scripts/backlog-vault/text-records.ts newest S<N>`, an edit not yet applied included; `pnpm backlog:search item S<N>` shows the same text with its GitHub state) and what it points to, and change that text only with `scripts/audit.sh edit S<N>` starting from it, never from the issue.
- Order: quote the `/goal` line and ACs word for word (`Goal for S<N>:`), the reuse check (the coordinator labels the issue `status:doing`), the grader written and shown **red on HEAD** before any product code, then your claim (run-backlog step 3.4: `node scripts/backlog-vault/claims.ts claim S<N> --root "$MAIN" --file … --symbol … --doc-line "<path>: <text>"`; on exit 1 commit a checkpoint with `pnpm verify` 0 and reply `needs-lead` with its report, then wait to be resumed), build inside the fence, grader green, the `**Baseline:**` line (`scripts/audit.sh edit S<N>`) and baseline rows (rule 17), `changelog.d/S<N>.md` (rule 16), `scripts/audit.sh story S<N>` exit 0 (it runs the grader and `pnpm verify`: your only local `pnpm verify` at the finish, so don't run one before it; owner, 2026-11-20: "Both (Recommended)"), the touched-files check (`bash -c '. scripts/lib/checks.sh; story_own_changed_files S<N> origin/stage .' | node scripts/backlog-vault/claims.ts touched S<N> --root "$MAIN"`; a file outside the claim goes in your reply), one commit on the branch you were given.
- Blocked (a design match or ratification, an AC that can't be met inside the fence, the turn cap, an owner decision): park it as run-backlog step 4 says and stop. A design match checkpoint is committed without captures: they are taken after the pre-PR review and its fixes, when the coordinator resumes you (a ratification has none). Never widen a fence, edit a `/goal` line or AC to pass, or write `RATIFIED.md` without the owner's words in the brief.
- Never push, open a pull request, start another story, or run a review (reviews need fresh context; the coordinator runs them).

Write your `Goal for S<N>:` quote and `S<N> verified:` section, exactly as written, and any long evidence (logs, file lists) to `"$MAIN"/.run/reports/S<N>-report.md` (`mkdir -p "$MAIN/.run/reports"` first). Reply in at most about 150 words (owner, 2026-11-24, among the token savers offered: "Do all 6 token savers"), with only: **outcome** (`done`, `parked` or `needs-lead`); the **commit** sha; a **one-line impact**; the report's path; if parked, each question for the owner (bold direct question first, then self-contained context) and any drift event (turn cap, fence).
