title: Pages that read the database load faster on staging and production
---

- **Pages that read the database, like the day's game digest, should load much faster: the app now runs close to its database instead of wherever a fan's request lands.** On staging, a cold 15-game digest took 8–12 seconds, most of it spent waiting about 70 ms for each of over a hundred database trips across the country. Staging gets it when this merges, production with the next release. Details: **B532** (#532) — Cloudflare Smart Placement (`"placement": { "mode": "smart" }`) on `wrangler.jsonc`'s `env.staging` and `env.production` only, so local dev and pull-request previews keep the default; it moves the fetch handler only (the cron's scheduled handler and the Durable Objects stay where they run today; static assets are still served nearest the fan), and Cloudflare can take up to 15 minutes after a deploy to place it. `functions/src/deploy/bootstrap.test.ts` pins it.
