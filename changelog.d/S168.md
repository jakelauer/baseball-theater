title: Checks run only for what a change touches
---

- **Before, every change to Baseball Theater, even one line in one corner, re-ran nearly every check in the whole project, one after another, which slowed each fix on its way to fans. Now each part of the project checks itself, the parts run side by side, and a change re-runs only the checks for what it actually touches, while every update to the staging site still re-checks everything from scratch, so nothing slips through. On the same machine, a one-line change to the web app now finishes in about 3½ minutes instead of 7.** Details: **S168** — ADR-030: workspace units (`@bt/scripts`, `@bt/tools`, `@bt/e2e` added) with their own `lint` / `typecheck` / `test` / `build` tasks, edges only to dependencies' `typecheck`, every input declared; `pnpm verify` narrows to the merge base with `stage` (`--all` for the finishing gate, `BT_VERIFY_FULL=1` for a fresh full run, as CI's pushes and Deploy's `verify` use); `audit.sh story` records ran / replayed / not affected; new laws L14–L17.
