title: Safer rollbacks for cached-page corrections
---

- **Before, rolling the site back to an older release could hold up corrections to cached scoreboards and games for up to a month, because the older code would send the edge cache a batch of addresses it refuses, and that refusal stalled the good ones sent with it. Now, older code never picks up those entries, and the current code still clears them on its next minute, so corrections reach the cache on time whichever release is running.** Details: **S219** — path-only owed purges (from S161's win-probability fill) keep `retry_at` at `'infinity'`, which a pre-S161 Worker's listing never reaches, and their real retry time in a new `path_retry_at` column (migration `0007_owed_edge_purge_paths`, which also hides rows already owed); from #572.
