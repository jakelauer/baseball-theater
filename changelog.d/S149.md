title: Live scores reach the scoreboard the moment BT has them, and it shows the Live marker
---

- **Before, the scoreboard caught up with live scores by asking again every few seconds, and could never say it was live. Now, while a game on the shown day is in its live window (from 2 hours before first pitch to 3 hours after the game), the scoreboard holds one live connection for the whole day: new scores, postponements and other schedule changes arrive as soon as BT stores them, and the footer shows the glowing "Live Data · Active" marker while the connection is open. If the connection drops it reconnects, and falls back to asking again, as a game page does.** Details: **S149** — a `day-hub:<date>` Durable Object (`DayHubObject`, `DAY_HUB`, migration `v3`) holds each day's viewers over hibernated one-way WebSockets and pushes S150's read-only served day, versioned (ADR-022); it leases every in-window game's ingest object, which publishes to it after each write or mend, and the schedule writers call it once per refresh or fill for each changed in-window day; `GET /api/v1/schedule/live?date=` upgrades only an in-window day (`scheduleDayWindowMode`), its refusals `no-store`; the client's `useLiveDay` runs on the game stream, generalized as `LiveStream`.
