title: A rebuilt staging or production database connection no longer serves minute-old reads
---

- **Before, when a deploy set up staging's or production's database connection from scratch, the connection kept a copy of recent reads for up to a minute, so a live score could stall for that long while BT kept judging its own update as not new. Now a connection a deploy creates always reads the database as it is.** Details: **B408** (#408) — `findOrCreateHyperdrive` created `bt-staging` and `bt-production` without `caching: { disabled: true }` (previews already passed it), leaving Hyperdrive's default 60 s query cache on under BT's read-then-version-guarded writes (ADR-022). Turning caching off on the two configs that already exist is a separate owner step.
