title: The plan's GitHub issues are checked against their agreed text, and anyone can suggest work
---

- **Before, a story's text changed on GitHub, a status gone wrong, or a screen started before its design was agreed went unnoticed, and an issue someone outside the team filed sat unseen. Now every check run compares the stories on GitHub with their agreed text and flags anything changed without a record, the owner can change a story on GitHub and have it recorded, and issues others file are labelled for the owner's decision, with nothing built from one until the owner accepts it.** Nothing in the app changes. Details: **S165** — `pnpm backlog:check --live` (`scripts/backlog-vault/live-check.ts`, in CI's docs and verify jobs with `issues: read`), `scripts/audit.sh edit --adopt`, `pnpm backlog:triage` and INDEX's Triage section, `pnpm backlog:areas` (area labels, done stories' milestones), the design gate in `claims.ts claim`, `audit.sh edit --review` refusing in-flight items, law L9's row.
