title: Each backlog run leaves a record, and the next run reads it
---

- **Before, whether the agents could safely work on three backlog items at once instead of two rested on a run summary nobody kept. Now every run leaves a record of how many items it ran side by side, where its time went and whether it ran clean, the next run reads the last records to choose how many to run at once, and a story that runs out of its turn budget automatically calls for a plan review.** Nothing in the app changes. Details: **S158** — the run journal (`claims.ts run start|event`, `.run/run.json`), `scripts/backlog-vault/runs.ts` (`summarizeRun`, `concurrency`), the `run` ledger entry (`scripts/audit.sh run [--abandoned]`), and turn-cap hits in `scripts/review-debt.sh` until a review lists them (`audit.sh review --debt-json`).
