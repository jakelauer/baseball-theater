title: The browser-test picker and the API type generator work however they are started
---

- **Before, the pull request check's browser-test picker and the web app's API type generator quietly did nothing, and still reported success, when started through a linked folder. Now both run the same however they are started, so the picker can never skip the browser tests by accident and the generator always writes the types.** Nothing in the app changes. Details: **S169** — `e2e/select-specs.ts` and `web/src/api/codegen.ts` decide whether they were started as a command with `import.meta.main`, which resolves symlinks, instead of comparing `process.argv[1]` with their own path (issue #315); each has an end-to-end test that starts it through a symlinked folder.
