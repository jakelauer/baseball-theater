**Gap:** The owner asked for a Download button on the video player (owner, 2026-11-12: *"video player needs a palette of helpful clickables (copy link, direct link, download, share)"*), then had it taken out (owner, same day: *"Remove the download button for now, but make a story to do the service worker in the future"*). A browser ignores `download` on a link to another site's file, so a plain link to MLB's MP4 only opens it; PR #58 built Download as such a link, so it opened the file like Direct link does, and the other way to save a cross-origin file, fetching the whole clip into the page first, holds a condensed game (hundreds of MB) in memory and can crash a phone's tab. The app already has a service worker (S73, ADR-023), and a service worker can answer a same-site request by passing MLB's file through as an attachment as it arrives, with no size limit and no server cost, since the bytes still come straight from MLB.

**Impact:** Before S151, saving a video meant opening it with Direct link and saving it from the browser's own player. S151 impact: Download saves any MP4 clip, a condensed game included, straight to the device.

**Acceptance criteria** (checks `scripts/verify-S151.sh` performs)

1. The service worker answers a same-site download route (for example `/download/clip?url=<MLB MP4>&name=<file name>`) by fetching the MP4 and passing its body through unread, with `Content-Disposition: attachment`, so nothing holds the whole file in memory, and MLB's `Content-Length` passed through so the browser shows progress. The name is never the caller's as given, and both header parameters end `.mp4`: first a trailing extension (`.` plus 1–4 letters or digits at the very end, `/\.[A-Za-z0-9]{1,4}$/`) is dropped from the title; then `filename` is its ASCII slug, lower-cased, each run of anything but `a-z0-9` turned into one `-` and `-` trimmed from both ends (`clip.mp4` when the slug is empty), and `filename*=UTF-8''…` (RFC 5987, which browsers prefer) is the title with CR, LF, `"`, `/` and `\` removed and the rest percent-encoded, then `.mp4`. An upstream answer that isn't 2xx (a removed clip's 403 or 404), or a fetch that rejects (a network error, or a redirect under `redirect: "error"`), gets a 502 with no `Content-Disposition`, so an error page is never saved as a video (unit tests of the handler with a fake `fetch`: the response streams the upstream body and carries `Content-Length` and both name parameters; `name=Acuña's homer` gives `filename="acu-a-s-homer.mp4"; filename*=UTF-8''Acu%C3%B1a%27s%20homer.mp4` and doesn't throw; `name=x.exe` gives `filename="x.mp4"; filename*=UTF-8''x.mp4`; `name=Ohtani reaches 50-50 vs. Marlins` keeps every word; `name=満塁弾` gives `filename="clip.mp4"; filename*=UTF-8''%E6%BA%80%E5%A1%81%E5%BC%BE.mp4`; an upstream 404 and a rejected fetch each answer 502).
2. The route serves only MLB clip MP4s, decided on the parsed URL, never the raw string: `protocol` is `https:`, `port` is empty, `username` and `password` are empty, `hostname` is exactly one of MLB's clip hosts (today `mlb-cuts-diamond.mlb.com`, `bdata-producedclips.mlb.com`, `darkroom-clips.mlb.com`, as the recorded content shows), and `pathname` ends `.mp4`. Anything else, or a malformed `url`, answers 400 and fetches nothing, so the route is never an open proxy; the upstream fetch uses `redirect: "error"`, so a 30x can't lead it elsewhere. One named, exported function in `packages/domain/src/video-quality.ts` (not `MP4_SHAPE`, which only `mlb-cuts-diamond` file names match) decides "an MLB clip MP4", and both this route and AC 4 call it (ADR-025). Tests: each host's real shape is accepted (`https://mlb-cuts-diamond.mlb.com/…_1280x720_59_4000K.mp4`, `https://bdata-producedclips.mlb.com/<uuid>.mp4`, `https://darkroom-clips.mlb.com/<uuid>.mp4`); each of these answers 400 without a fetch: `https://mlb-cuts-diamond.mlb.com.evil.example/<uuid>.mp4`, `https://evil.example/mlb-cuts-diamond.mlb.com/<uuid>.mp4`, `https://mlb-cuts-diamond.mlb.com@evil.example/<uuid>.mp4`, `https://user:pw@mlb-cuts-diamond.mlb.com/<uuid>.mp4`, `http://mlb-cuts-diamond.mlb.com/<uuid>.mp4`, `https://mlb-cuts-diamond.mlb.com:8443/<uuid>.mp4`, `https://mlb-cuts-diamond.mlb.com/<uuid>.m3u8?x=.mp4`.
3. The worker (a bundled source under `injectManifest`; see the notes) keeps what `generateSW` gave for free: it precaches the same files (its `injectManifest.globPatterns` match the old `workbox.globPatterns`, and `web/src/pwa/pwa.test.ts` asserts the `injectManifest` options, not the `workbox` block that `injectManifest` ignores); it answers navigations with `/index.html`, denying `/api/` and the download route; and it answers `updates.ts`'s `{ type: "SKIP_WAITING" }` message (unit tests of the worker's handlers for each; see the notes), so Update Now still works. `e2e/flows/update.spec.ts` is not among the story's changed files (`story_changed_files`).
4. The player's palette (`PlayerActions`) shows **Download** again, as a link to the route for the clip's MP4 (`fileUrl`, `fileQuality`), only while the worker controlling the page answers for that route: the page asks it (a `postMessage` ping the new handler answers, checked again on `controllerchange`), since an older worker still in control under the update prompt (`registerType: "prompt"`) would answer the route with the app shell. With no controller (a first visit before the worker takes over, a private window that refuses it), an older one, no MP4 of the cut playing (`fileUrl` null), or an MP4 not on MLB's clip hosts (AC 2's function says no) it shows none, and Copy link, Direct link and Share are unchanged (RTL for each case).

**Notes:**

- The app's worker is generated today (`vite-plugin-pwa`'s default `generateSW`, `web/src/pwa/options.ts`). A fetch handler that calls AC 2's domain function needs `injectManifest` with a bundled worker source under `web/src/` (adding `workbox-precaching` / `workbox-routing` to `web/package.json` and `pnpm-lock.yaml`). Give the worker its own `web/tsconfig.sw.json` with the `webworker` lib and exclude it from `web/tsconfig.json`, since one file under both the `dom` and `webworker` libs raises duplicate declarations; the fence's `web/tsconfig*.json` is a shell glob (the grader matches it with a `case` pattern). `encodeURIComponent` leaves `'`, `(`, `)` and `*` alone, which RFC 5987 requires encoded (the `%27` in AC 1's test catches it). Keep the handlers (download route, navigation fallback, `SKIP_WAITING`) in a module with no side effects on import, which the tests import, and a thin worker entry that wires them up and calls `precacheAndRoute(self.__WB_MANIFEST)`. `workbox.importScripts` (a script in `web/public/`, never bundled) and a `generateSW` `runtimeCaching` handler (turned into text inside `sw.js`) can't import `@bt/domain`, so they can't meet AC 2.
- Safari's service-worker streaming is the risky one. If a browser can't stream it, the worker doesn't answer AC 4's ping there (feature-check `ReadableStream` passthrough in the worker), so Download stays hidden rather than falling back to holding the file.
- MLB's CDN answers `access-control-allow-origin: *` on these files (checked 2026-11-12), so the worker's `fetch` can read them.
