Carries the fixes for #79 (suspended, MLB `T`/`U`) and #80 (forfeited, MLB `Q`/`R`) and any other mismatch between BT's status table and MLB's full list (owner, 2026-11-20, asked whether #79–#81 should become stories: *"#81 should include fixes to 79 and 80, in addition to any other status mismatches discovered therein"*). The fix's pull request says `Fixes #79, Fixes #80, Fixes #81`.

- **Forfeited** (`Q`, `R`): final.
- **Suspended** (`T`, `U`): looks live and keeps being polled for up to 6 hours (owner, 2026-11-20: *"It should look like a live game in the UI in that the user should be able to see what happened so far in the game, but it should be clear to the user that the game is suspended and polling should continue for up to 6 hours."*). Told that a suspended game normally resumes on a later date, the owner chose to fix it now and design the marker after (*"Fix now, design after (Recommended)"*): B81 ships no suspended marker, since none is ratified (rule 18); S157 designs it. "Looks live" is the game page's phase and rooms only (`gamePhase`, `packages/domain/src/game-phase.ts`); window membership is a separate rule, so suspended codes don't join `LIVE_CODES`, whose games stay in the window whatever the clock says (`isGameInActiveWindow`, `packages/domain/src/window.ts`). The 6 hours run from when ingest first sees the game suspended (stored on the game, since nothing records it today; the fix says where); after them the game drops out of the ingest window until MLB marks it in progress (`I`) on the day it resumes. BT's own unknown code is also `U` (`normalizeStatusCode`), so the fix gives suspended games their own `GameStatusCode` and unknown statuses a code MLB doesn't use, and updates every caller that switches on `GameStatusCode` in `packages/`, `functions/` and `web/`.
- **Any other mismatch:** #81's test compares BT's table to a recorded fixture of MLB's full `/api/v1/gameStatus` list, so every code MLB lists today is handled, and `pnpm mlb:scan-drift` (offline from that fixture, or re-recording it with `BT_USE_LIVE_MLB=1`) reports a code MLB adds later; CI never calls MLB. A code whose meaning needs an owner decision parks the bug as a question rather than being guessed.
