# A7 — A status marker says when a game is suspended or delayed (S157)

Amends the ratified [game-shell design](../DESIGN.md) (ratified 2026-10-14) and its amendments [A1](A1.md)–[A6](A6.md), and, for the scoreboard's game rows, the ratified [shell-scoreboard design](../../shell-scoreboard/DESIGN.md) and its amendments. Story **S157**; a build story, added once this amendment is ratified, builds it. **Draft, not ratified.** Nothing here is ratified until the owner says so; until then the frames and the component are a proposal.

**Adds:** the `game-status-marker` component set (Components page): the dot and label that say a game's status, in three states, `State=Live`, `State=Delayed` and `State=Suspended`, each in two places, `Place=Top bar` (inside the `game-topbar`) and `Place=Row` (the top-left of a scoreboard game row, the `Rich Scoreboard Module`). A delayed game reads "● DELAYED · RAIN" in the top bar and "● Delayed · Bot 3" on its row, with a steady `Accent` dot; a suspended game reads "○ SUSPENDED" in the top bar and "○ Suspended · Top 5" on its row, with a steady `Accent` ring.
**Overrides:** the live indicator drawn in the `game-topbar` ("● LIVE", S36 R6) and the live row's status ("● Bot 7", shell-scoreboard frames): both were copies of one dot and label, and both are now instances of `game-status-marker` at `State=Live`, which looks exactly as they did (an `Accent 2` dot, blinking, and its label). Neither is shown for a delayed or suspended game any more: the marker's other states replace them.
**Repeals:** nothing.

## Decisions

Recorded as the owner stated them. On #79, 2026-11-20, of suspended games: "It should look like a live game in the UI in that the user should be able to see what happened so far in the game, but it should be clear to the user that the game is suspended and polling should continue for up to 6 hours." Asked how to handle it, the owner chose "Fix now, design after (Recommended)", offered as "A design story then draws a status label for suspended (and delayed) games for you to ratify". On #72, 2026-11-17, of rain delays: "Yes, a rain delay should show the live tab."

What the draft proposes (agent's reading of those words, for the owner to ratify or change):

- **Marker:** a dot and a label, as the ratified live indicator is: an 8px dot, then 6px, then the label in 12px IBM Plex Sans Bold, in the dot's colour, no pill and no background (VISUAL-DESIGN's live role). In the top bar the label is upper case, as "LIVE" is; on a row it is sentence case with the inning, as "Bot 7" is.
- **One component:** `game-status-marker` is one component set with a variant per state and place, and every frame places an instance of it: the `game-topbar` component's `live-indicator` and the `Rich Scoreboard Module`'s live `status-group` now each hold an instance (`State=Live`), so the ratified frames look as they did, and a change to the marker reaches every frame. Before this the dot and label were drawn twice, as copies (the top bar's "● LIVE" and the row's "● Bot 7"); they were alike but for their words, so nothing had to be chosen between them.
- **Codes:** `State=Live` is a game in progress: MLB `I` with no delay reason (`I` "In Progress", `IH` "Instant Replay"), a manager challenge `M` and an umpire review `N`. `State=Delayed` is an in-game delay: MLB `I` whose detailed state starts "Delayed" (`IR` "Delayed: Rain", and `I9`, `IA`–`IG`, `II`, `IL`, `IO`, `IP`, `IS`, `IT`, `IV`, `IY`, `IZ`); its label names MLB's reason after the dot ("DELAYED · RAIN"; plain "DELAYED" for `IO`, which gives none). `State=Suspended` is MLB's `T` and `U`, every reason (B81's code list, `packages/domain/src/window.ts`). A delayed start before first pitch is MLB `P` (`PR` "Delayed Start: Rain" …), which has no Live room; whether it gets the marker is open question 1.
- **Top bar:** the marker takes the live indicator's place, after `NYY @ BOS`, for a game in progress, delayed or suspended; a scheduled or final game shows none, as ratified (game-shell DESIGN, "No status"). The Live tab stays for all three, so the play so far stays visible (owner, 2026-11-20).
- **Scoreboard row:** the marker takes the status place at the top-left of the row, and keeps the inning after the state ("Delayed · Bot 3", "Suspended · Top 5"), so the row still says where the game stopped. The score, the team rows and the slot stay as for a live game.
- **Motion:** only `State=Live` blinks (VISUAL-DESIGN's slow live blink); delayed and suspended are steady, since nothing is happening, and so need nothing under reduced motion.
- **Resumed:** once a suspended or delayed game resumes (MLB reports it `I` again with no delay reason), the marker goes back to `State=Live`, "● LIVE" and "● Bot 7", blinking, with nothing to say it was stopped. A suspended game that BT stops polling (6 hours after it saw it turn suspended, B81) keeps "○ SUSPENDED" from its last stored status until a schedule read sees it resume or end. A suspended game that resumes on a later day reads "● LIVE" on that day; the earlier day's row reads whatever BT last stored for it.
- **Footer:** unchanged: A13's "● Live Data · Active" strip follows the page's live connection, not the game's state, so a delayed or suspended game whose page is still connected shows it (drawn so in the game frames).

## Open questions

1. **Q1.** **Should a game whose start is delayed (MLB `P`, e.g. "Delayed Start: Rain", before first pitch) show the marker too, or stay a plain scheduled game until it starts?** A delayed start has no Live room (it is pre-game) and today reads as scheduled: no marker in the top bar, its start time on its row. The draft gives it no marker. The other reading: its row and top bar show "● Delayed start · Rain" in the same `Accent` as an in-game delay, so a fan sees why it hasn't started; that adds a frame for it before ratifying.
2. **Q2.** **Are a steady gold dot for a delay and a steady gold ring for a suspension clear enough, or should they use other colours or shapes?** As drawn (`game-status-marker`, Components page), delayed and suspended both use `Accent` (#F5AD1D), the warm highlight, so neither reads as live green or as the red of strikes; the ring marks a suspension as more stopped than a delay. Other readings: muted grey for suspended, as Final is; a pause glyph instead of a ring; or one shape for both.
3. **Q3.** **Should the suspended label name MLB's reason too ("SUSPENDED · RAIN"), as the delay label does, or stay "SUSPENDED"?** MLB gives a reason for most suspensions (`TR` "Suspended: Rain", …). The draft names the reason only for a delay, since a delay's reason says why fans are waiting while a suspension's matters less once the game is put off; naming it for both is just as easy to build.
4. **Q4.** **Once a suspended game has resumed and finished, should anything say it was suspended (for example on the earlier day's scoreboard row), or is a plain Final enough?** The draft shows nothing extra: a resumed game reads "● LIVE" and then Final like any other, and its earlier day's row shows what BT last stored.
