# A13 — A Live marker replaces "Fetched … ago" (S147)

Amends the ratified [shell-scoreboard design](../DESIGN.md) (ratified 2026-10-14) and its amendments [A1](A1.md)–[A12](A12.md), and through them the footers of the ratified game-shell, game-rooms and standings-search-settings frames. Story **S147**; built by S148. **Draft, not ratified.**

**Adds:** the Live marker (component `live-marker`): an 8px red dot (`Primary Light`, #FF5247) with a red glow, and the word "Live" beside it (11px IBM Plex Sans Medium, primary text), at the foot of any page that has an open live WebSocket. The dot glows and blinks slowly: it fades between the `Phase=Bright` and `Phase=Dim` variants and back, about 2 seconds a cycle, easing in and out. With reduced motion it stays at `Phase=Bright`, glowing, and does not blink.
**Overrides:** the footer line "Fetched {age} · baseball.theater" (the `footer-meta` component, and every ratified frame that draws it: the shell-scoreboard frames, game-shell A3, game-rooms A4, shell-scoreboard A4, the Standings frames). The "Fetched {age}" part is removed everywhere. On a page with an open live WebSocket the line reads "● Live · baseball.theater", the marker in place of the age; on every other page it reads "baseball.theater" alone. Those frames stay sealed and differ from a build only in this line.
**Repeals:** the "Fetched {age}" label, and ADR-014's "Freshness is visible" row as far as it asked for that label (ARCHITECTURE.md, amended in the same change set).

## Decisions

Recorded as the owner stated them. On 2026-11-10: "just get rid of the fetched label" (S141). Asked on 2026-11-16 whether ADR-014's "freshness is visible" promise (and VISUAL-DESIGN D9) should be dropped now that the "Fetched … ago" line is going: "Remove the fetch label and replace it with a red dot and Live at the bottom of any page that has an active websocket, with the red dot glowing and slowly blinking".

## Interpretation

- *Agent:* "a page that has an active websocket" is, today, a game page whose game is in its live window with its stream connected (`useLiveGame`, `web/src/api/live.ts`). The scoreboard, Standings, Search and Settings open no WebSocket (the scoreboard polls), so they show no marker; a page that later opens one shows it with no further design.
- *Agent:* "active" means the socket is open. While it reconnects after a drop, or after it has given up and fallen back to polling (`LIVE_TIMING.maxFailures`), the marker is hidden, so it never claims pushes that aren't arriving.
- *Agent:* "at the bottom" is the footer line, where "Fetched … ago" was, at the end of the page's content, not pinned to the bottom of the screen. When S141's footer of links replaces the line (S142), the marker keeps a place in it, which S141 draws.
- *Agent:* the red is `Primary Light`, the design's readable red on dark; the glow is a drop shadow of the same red.
- *Agent:* the offline footer ("Offline · saved … ago", A1 and game-rooms A1) is not a "Fetched" label and stays; offline there is no socket, so no marker.

## Open questions

1. **Q1.** **Is it right that the scoreboard shows no Live marker, since it refreshes by polling every 15 seconds rather than over a WebSocket?** Drawn so, to your words "any page that has an active websocket". The other reading: the scoreboard shows it too while any game on it is live. **Answered 2026-11-16:** *"the scoreboard should have a live connection"*, opened only *"While a game is live"*, through *"One socket per day"* (S149 builds it). So the scoreboard shows the marker while any game on its day is in its live window (2 hours before first pitch to 3 hours after the game, the window game pages use) and its connection is open; the scoreboard frames are to be redrawn with a live game and the marker before ratifying (S147 AC 1 and AC 2).
2. **Q2.** **The game's top bar already shows a green "● LIVE" when the game is in progress; is a second, red "Live" at the foot of the same page clear enough?** The top bar's says the game is being played; the footer's says this page is receiving updates live. Keep both as drawn, or change the footer marker's word (for example "Live updates").
