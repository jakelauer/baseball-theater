The grader checks both lines exist with quotations; ACs 4 and 5 implement them, and the grader is updated under rule 7 to their numbers.
2. **Answers only from the game's data.** `POST /api/v1/games/:gamePk/chat` takes `{ question }` (1–500 characters; 400 otherwise) and answers `AiOutputResponse<ChatAnswer>` (`text`, and `known: false` when the answer is "I don't have that"). The model gets S177's chat pack for that one game as cacheable fixed input (so a second question about the game bills it at the cache price; adapter test on a recorded response shows cached input tokens) and the question as untrusted data: its instructions say to answer only from the pack and otherwise say "I don't have that", and a question telling it to ignore them changes nothing (test with the stub asserting the question never lands in the fixed instructions).
3. **The lighter loop.** Each answer goes through S176's `writeVerified` with chat's options: the rules checker only (no fact-checker agent call), at most one revision, and an answer that still fails is replaced by "I don't have that" (`known: false`), never sent unchecked. Tests: a computable question answered from the pack (the starter's pitch count equals `pitcherLine`'s); a wrong number caught and revised; a second failure answered "I don't have that"; a question the pack can't answer.
4. **Who may chat, and how much.** One domain function, `chatAllowance(session, usedToday)`, implements the owner's answer to question 1 (who may chat and the daily caps per kind of account); a refused request answers 403 (not allowed) or 429 (cap reached, with when it resets, the next UTC midnight). Each account's count per UTC day is stored and incremented atomically before the model call (contract test: two racing requests at the cap, one refused); a request answered `output: null` because no model is configured, the budget refused its first call, or the call failed in transport gives its count back, to the UTC day it was taken from (a request at 23:59:59Z refunded after midnight restores the earlier day), and an answered one, `known: false` included, keeps it. A budget refusal mid-loop, after a paid draft, answers `output: null`, refunds the count, and keeps the paid draft only in S184's store, never shown (tests for each). A table test covers each kind of account the answer names.
5. **Near the monthly cap.** Chat stops as the owner's answer to question 2 says (with the precompute jobs at the $100 stop, or earlier to leave room for them), through one function beside `aiBudgetState`; test at each boundary.
6. **A fan's questions are personal data, kept apart from S176's log.** Chat's questions, answers and loop rounds are stored only in S184's own store (through `writeVerified`'s `logSink`, S176), never in S176's shared AI log, which stays `none`; the store is tied to the account, labeled `personal` in the classification manifest with a registered `PersonalDataStore` that exports them, and AC 4's per-account daily counts with them, in the fan's download and deletes both with the account (ADR-028; law L3; the deletion contract test runs it); nothing about a question is written to logs (law P5).
