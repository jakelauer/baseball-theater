**Acceptance criteria** (checks `scripts/verify-S90.sh` performs)

2. **What the data holds, season by season.** `pnpm pitch-model:data-check --from <day> --to <day>` (a script under `functions/src/scripts/`) reads the games BT stores for that range and writes, per season, into `docs/v3/pitch-model/data-check.md`: games and pitches, the share of pitches with a pitch type, speed, plate location, movement, spin and result, the pitch-type labels used, and the consistency checks it ran (each at-bat's pitches reach its final count; each game's pitches match its final box's pitch counts), with the games that fail them. A test runs it on the committed sample.
3. **Pre-pitch examples, never peeking ahead.** One pure function in `packages/domain`, `buildPitchExamples(game, windows, priorGames)`, walks a game's pitches in order and, for each pitch the data supports, returns an example: the state just before it (inning, half, outs, runners, score, count, the pitcher and his throwing hand, the batter and his side, pitch numbers in the at-bat and the game), its history windows of preceding ordered events in their raw form (each pitch's type, speed, location, movement and result, no statistics computed from them), and the target (the pitch that followed: its type, and its location, speed, movement and result for later phases). `windows` is a list of window definitions; S90 builds one kind, the most recent N pitches of this game (N in the definition), and S187 adds the others. `priorGames` is the history source for windows that reach into earlier games: the caller supplies the earlier games' pitches (empty for S90's window kind), so the training export and S190's live path load the same history the same way. Tests: for every pitch of the 823823 fixture and of an invented game, the **state and windows** of pitch *n*'s example equal those built from the same game cut off just before pitch *n* (the target is left out of the comparison, since the cut-off game doesn't hold it), so nothing after the pitch can reach them; a prior game dated on or after the current game is refused; a pitch with no type is a target the example marks missing, never guessed; an example's target never appears in its own state or windows.
4. **Exported for training.** `pnpm pitch-model:export --from <day> --to <day> --out <file>` writes the examples of every stored game in that range, oldest game first, as JSON lines with a schema version and each example's game id and date, so later phases can split whole games by time. A committed sample under `fixtures/pitch-model/` (the 823823 game and enough others for at least 1,000 examples; a test counts them) keeps tests offline, and a test under `ml/` reads the sample with the same schema version.
