**Gap:** S176 can call four AI providers, but nothing says which model should write which piece. Asked which provider, the owner answered (2026-11-22): *"I would like a cost comparison as all as an evaluation as to which is likely to be most effective at this category of work"*. The research's addendum (`docs/v3/AI-RESEARCH-2026-11.md`, A–D) answers: Anthropic's and OpenAI's best mixes tie at about $22 a month, Google's is third at about $33, no public benchmark covers baseball, and a blind test on 40 of BT's own games should decide (addendum D). Each job also needs the facts BT hands the model, its instructions and its output schema, which no story has written yet.

**Impact:** Before S177, picking an AI provider for BT would have been a guess from benchmarks about other kinds of writing. S177 impact: every candidate model writes the same pieces about the same 40 real games, BT scores them for wrong facts, format, picking what mattered, chat answers, baseball rules, cost and speed, and the owner picks blind among the ones that pass; the choice is written down, and the test can be re-run whenever a new model comes out.

**Acceptance criteria** (checks `scripts/verify-S177.sh` performs), following the research's addendum D:

1. **The owner approves the test's spend first.** Before the first full run, the owner approves its API fees (addendum D: about $100–150, plus the fact-checker calls and revisions of AC 4, so up to about twice that), which are paid from a developer machine with the owner's keys and do not count against production's $100 monthly cap; this story's text gains an `**Owner approved the test's spend:**` line quoting the amount and the owner's words (`scripts/audit.sh edit`). The run script refuses to start when its own cost estimate passes `--budget` (default: that amount) (test with the stub). The run injects its own in-memory `AiSpendRepository` (with `--budget` as its cap), in-memory cache and in-memory log; a test shows it touches no Postgres at all (no Postgres adapter is constructed and no database connection is opened), so nothing reaches production's meter, cache or log. Missing provider keys or a missing spend approval park the story (`status:blocked`, a checkpoint commit) before any paid call.
2. **Forty frozen games.** `fixtures/ai-eval/games.json` lists 40 finished games with why each was chosen, and the set includes at least: blowouts, one-run games, walk-offs, extra innings, a no-hit or perfect-game bid, a rain-shortened game, 5 postseason games and games with ABS challenges (a test counts each category against the list). Each game's data is recorded with `BT_USE_LIVE_MLB=1` (the existing recorder) or exported from the stage database, and frozen under `fixtures/ai-eval/`, so every model sees byte-identical input (a test hashes each frozen file against the manifest). Before committing, the frozen data's size is measured; if the 40 games pass 20 MB together, they are committed as compact projections holding only the fields the fact packs read, and a test builds each fact pack from a projection and from the full game and finds them equal.
3. **Each job's facts, instructions and schema, once.** `packages/domain` gains one fact-pack function per job, each a pure function of BT's stored game data and tested on fixtures: the recap and the package (the final, the lines that stood out, the key moments ordered by win probability added, through one function `topPlaysByWinProbabilityAdded(game, n)` that reuses `impact.ts`' measure), an inning's notes, a play's explainer, a day's digest (from the day's game facts) and a game's chat pack. Each job's fixed instructions, output schema and few-shot examples sit beside it with a `promptVersion`. No fact pack, instruction or example holds MLB's editorial recap text (a test checks the packs' keys; the research's §4). The feature stories (S178–S184) reuse these and bump `promptVersion` when they change one.
4. **Every candidate, same input, through the loop.** Up to 9 writer models (Claude Haiku 5.5, Sonnet 5.5, Opus 5.5; gpt-6-luna, gpt-5.4-nano, gpt-6.2-sol; Gemini 3.5 Flash-Lite, Gemini 3.1 Pro; Gemma 4 26B on Workers AI, or their successors when the test runs, each listed in the report) write, per game, 1 recap, 1 package headline and narrative, 3 inning-notes calls (chosen innings, the same for every model), 3 play explainers and 5 chat answers from a fixed question set (3 BT can compute exactly, such as "How many pitches did the starter throw?"; 1 rules or situation question, such as "Why was that run unearned?"; 1 the data can't answer, where the right answer is "I don't have that"), plus 5 day digests. Each piece goes through S176's `writeVerified` (chat with its lighter options) with the same instructions and schema; only the writer's adapter changes, and the fact checker is the strong model of a provider other than the writer's (named in the report). Low effort, default temperature.
5. **Scored, mechanically except for preference.** `pnpm ai-eval:report` writes `docs/v3/ai-eval/<date>.md` with, per model and per job:
    1. **Factual errors** in what would be published: the rules checker's findings, plus every claim it can't check judged by a model from a provider other than both writer and checker, with 10% of items spot-checked by the owner. Bar: at most 1 unsupported claim per 100 and at least 95% of outputs with none. The first drafts' error rate is reported beside it.
    2. **First-try pass rate** (the share of items whose first draft passed both checks) and **average revisions** per item, and the share that failed after the cap (added 2026-11-22, when the owner's verification loop joined S176). Bar: at most 5% of items failed after the cap; the pass rate and revisions also enter measure 7's cost.
    3. **Format:** matches the schema and length limits, one retry allowed. Bar: 100% after the retry.
    4. **Picked what mattered:** the recap or package mentions the game's top 3 plays by win probability added. Bar: at least 90% of games.
    5. **Chat accuracy:** exact match on the computed answers, a correct "I don't have that" on the unanswerable one. Bar: at least 90% of each.
    6. **Baseball correctness:** the rules questions, plus rule errors the owner flags in the blind review. Bar: none flagged in more than 1 of the 40 games.
    7. **Projected cost and speed:** from each call's reported usage, loop included, scaled to BT's season month (about 450 games, 4,500 innings) plus 2,000 chat turns. Bar: the month at most $100; a live job (inning notes, explainers) done, revisions included, within 10 seconds.
6. **The owner's blind preference, for the recap and the package.** Only models that pass measures 1–7, up to 4 finalists: `pnpm ai-eval:prefer --job recap|package` shows 20 games' pieces in pairs in the terminal, labels hidden, order random from a recorded seed, records each choice in `fixtures/ai-eval/preferences.json` and each model's win rate in the report. The other jobs (inning notes, explainers, digest, chat) are chosen by the measures and cost alone (AC 7), unless the owner asks for a blind pair set for one of them, which the same command then runs with `--job`.
7. **The decision, recorded.** The report applies the decision rule per job, over the models that pass measures 1–7: for the recap and the package, the highest blind win rate, except that a cheaper passing model that loses by less than 10 points of win rate is chosen instead; for the other jobs, the cheapest passing model by measure 7. The owner then chooses, for each job, a writer and a fact-checker model, and ADR-007 in `docs/v3/ARCHITECTURE.md` records the choice with the owner's words quoted and a link to the report; `wrangler.jsonc` (or the config S176 reads) names those models. The grader checks the report exists, ADR-007 carries a quoted choice naming a writer and checker per job, and the config matches it. The story parks (`status:blocked`, a checkpoint commit) while it waits for the owner's review and choice.
8. **Repeatable.** One command, `pnpm ai-eval:run --models <ids> --budget <usd>`, re-runs the whole test on the frozen inputs, and re-runs only the jobs a changed `promptVersion` touches with `--jobs`; the report says the date, the price table's date and each model id.
