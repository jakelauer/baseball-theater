**Acceptance criteria** (checks `scripts/verify-S90.sh` performs)

1. **Does the order survive batched patches?** A test folds the recorded diffPatch walk of game 823823 (`fixtures/raw/diffpatch-823823.json` over `live-823823-base.json`, through `reconstructReplay`) and checks, at every retained timecode, that the pitches present are a prefix, in order, of the final feed's pitch sequence (the order `GameSnapshot.plays` gives); it counts the steps that added more than one pitch at once and shows each such batch still holds its pitches in order (each pitch event's index and start time). `docs/v3/pitch-model/data-check.md` records the answer: whether the order survives, how many batched steps the recordings hold, and, if any pitch can't be placed, which ones and why. If the order does not survive for some games, the report says so and AC 3 builds no example past the first pitch whose order is uncertain in that game (the brief's §2: account for lost history rather than invent it).
2. **What the data holds, season by season.** `pnpm pitch-model:data-check --from <day> --to <day>` (a script under `functions/src/scripts/`) reads the games BT stores for that range and writes, per season, into `docs/v3/pitch-model/data-check.md`: games and pitches, the share of pitches with a pitch type, speed, plate location, movement, spin and result, the pitch-type labels used, and the consistency checks it ran (each at-bat's pitches reach its final count; each game's pitches match its final box's pitch counts), with the games that fail them. A test runs it on the committed sample.
3. **Pre-pitch examples, never peeking ahead.** One pure function in `packages/domain`, `buildPitchExamples(game, windows)`, walks a game's pitches in order and, for each pitch the data supports, returns an example: the state just before it (inning, half, outs, runners, score, count, the pitcher and his throwing hand, the batter and his side, pitch numbers in the at-bat and the game), a history window of the preceding ordered events in their raw form (each pitch's type, speed, location, movement and result, no statistics computed from them), and the target (the pitch that followed: its type, and its location, speed, movement and result for later phases). `windows` is a list of window definitions; S90 builds one kind, the most recent N pitches of this game (N in the definition), and S187 adds the others. Tests: the example for pitch *n* of a game equals the example built from the same game cut off just before pitch *n* (for every pitch of the 823823 fixture and an invented game), so nothing after the pitch can reach it; a pitch with no type is a target the example marks missing, never guessed; an example's target never appears in its own state or window.
4. **Exported for training.** `pnpm pitch-model:export --from <day> --to <day> --out <file>` writes the examples of every stored game in that range, oldest game first, as JSON lines with a schema version and each example's game id and date, so later phases can split whole games by time. A committed sample under `fixtures/pitch-model/` (the 823823 game and at least two others) keeps tests offline, and a test under `ml/` reads the sample with the same schema version.
5. **Where training runs, measured.** Under `ml/`, one benchmark (load an export, train a small gradient-boosted model of S186's kind on it, score it) runs on at least three options that don't depend on the owner's own computer (for example a free hosted notebook, a rented cloud machine of about 8 vCPUs and 32 GB, and a managed training or batch service), each recording wall time, peak memory, data moved and money spent, extrapolated to the full dataset. Before the first paid run the agent tells the owner its estimated cost and records the owner's OK, quoted, in `docs/v3/pitch-model/compute.md`; the report compares the options there. The owner then picks one and sets the training budget (the brief's §13 suggests $25–50 to start), and this story gains `**Compute choice:**` and `**Training budget:**` lines quoting the owner (`scripts/audit.sh edit`), which the grader checks and later phases read.
