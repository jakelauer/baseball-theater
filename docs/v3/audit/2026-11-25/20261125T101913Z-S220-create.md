**Gap:** B532 turned on Smart Placement for the staging and production Workers (`wrangler.jsonc`: `"placement": { "mode": "smart" }`), which moves only the fetch handler near Neon (us-east-2). Cloudflare's documentation says cron runs and Durable Objects don't move with it, and both talk to Postgres: the per-game ingest Durable Objects (ADR-020; `functions/src/game-ingest-object.ts`, made with `namespace.get(namespace.idFromName(…))` and no location hint) and the per-minute cron (S194's month refresh, S212's 7-day re-check). Staging measured about 70 ms a round trip from far away (B532), so live ingest (pitch to screen) and the cron's budget may still pay it on every query. Enhancement #538, filed from B532 by its worker, suggested measuring after B532 deploys and then trying a Durable Object `locationHint` near us-east-2 or a placement hint; the owner, asked in `/pending` (2026-11-25) *"Which of these four enhancements should become stories?"*, chose *"All four (Recommended)"*.

**Impact:** Before S220, nobody knew how long the live game updaters and the minute-by-minute jobs wait on the database, and they may run far from it. S220 impact: BT logs how long they wait, and staging places the live game updaters near the database, so the numbers show whether production should follow.
