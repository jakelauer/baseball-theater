**Body**

<!-- bt-body:begin -->
**Gap:** Three design capture specs pick scoreboard games by where they sit on the page rather than which game they are: `e2e/design/S20.spec.ts:75` (`getByTestId("scoreboard-module").nth(1)`), `e2e/design/S170.spec.ts:234-249` and `e2e/design/S74.spec.ts:138` (`.first()`, commented as SF @ NYM, the day's first game). The scoreboard's default order became favorites, then live games, then the rest by start time (B429, B430), so these may now capture a different game than they mean to, and `pnpm verify` doesn't run the design specs (`pnpm design:capture <ID>` does, by hand), so nothing notices until a design match looks wrong. Enhancement #561, filed from the `scoreboard` bug group by its worker, suggested picking by id or phase; the owner, asked in `/pending` (2026-11-25) *"Which of these four enhancements should become stories?"*, chose *"All four (Recommended)"*.

**Impact:** Before S218, a design check could quietly photograph the wrong game after the scoreboard's order changed, wasting the owner's review. S218 impact: each check finds the game it means by the game itself, whatever order the scoreboard shows.
