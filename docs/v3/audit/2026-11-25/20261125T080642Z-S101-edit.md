- **A new extra must not slow a game fetch or add a request to every poll (2026-11-25 backlog review, after S216).** Since S216, `HttpMlbStatsClient.fetchGame` (`functions/src/adapters/http/mlb.ts`) fetches the live feed, then its extras at once, and answers a cold read without the play metrics once they pass `PLAY_METRICS_LIMIT_MS` (750 ms, S216 AC 5; `functions/src/services/ingest.play-metrics.test.ts`). Joined to that `Promise.all` unbounded, a slow or hanging uniforms request would hold every game read until it answered, and each live poll would call it again for a value that is settled before first pitch. So the call either runs off that path or under the same limit, and AC 5's test adds: a uniforms request that never resolves leaves `fetchGame` answering within `PLAY_METRICS_LIMIT_MS` with the field absent (review-class checklist items 3 and 7, partly present data and upstream request budget).
