**Gap:** Whether a game is a favorite team's (its away or home team among the fan's favorites) is worked out in two places. The domain's `scoreboardRows` (`packages/domain/src/scoreboard-rows.ts:30`) keeps it in a private closure, `favorite`, for Collapse Non-Favorites (S68); S74's open-time prefetch writes its own copy in the web client (`web/src/pwa/prefetch.ts:27`, `favorites.has(game.teams.away.id) || favorites.has(game.teams.home.id)`) to pick which games to fetch ahead. Two copies of one calculation is what ADR-025 forbids, and bug B430 (#430, the scoreboard's order putting favorites first) is about to need it a third time. Found by the 2026-11-24 (third) backlog review's duplication sweep.

**Impact:** Before S213, the scoreboard and the offline prefetch each had their own rule for "this is a favorite team's game", so a change to one (a doubleheader, a team that moves) could miss the other. S213 impact: there is one rule, which the scoreboard, the prefetch and the coming favorites-first order all use; fans see no change.

**Source:** Feature: Settings (favorites, hide scores, playback prefs)
