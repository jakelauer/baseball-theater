- **A new extra must not slow a game fetch or add a request to every poll (2026-11-25 backlog review, after S216).** Since S216, `HttpMlbStatsClient.fetchGame` (`functions/src/adapters/http/mlb.ts`) fetches the live feed, then its extras at once, and answers a cold read without the play metrics once they pass `PLAY_METRICS_LIMIT_MS` (750 ms, S216 AC 5; `functions/src/services/ingest.play-metrics.test.ts`). Joined to that `Promise.all` unbounded, a slow or hanging rule-settings request would hold every game read until it answered, and each live poll would call it again for a value that doesn't change during a game. So the call either runs off that path or under the same limit, and AC 5's test adds: a rule-settings request that never resolves leaves `fetchGame` answering within `PLAY_METRICS_LIMIT_MS` with the field absent (review-class checklist items 3 and 7, partly present data and upstream request budget). The reuse check's `packages/mlb-api/src/live.ts` is the place to ask whether `hydrate=ruleSettings` can ride on the live feed request `fetchGameFeed` already makes, with no request of its own; if it can, AC 3's method may read it from there, and the recording in AC 1 still holds the hydrated response.

- **Asked off the fetch path, kept across refreshes (2026-11-25 backlog review, after S99).** S99 asks its extra (the player of the game) only outside `fetchGame`, at each ingest path that writes a game (`ingestScheduleDay`, `readGames` and `tickIngest` in `functions/src/services/ingest.ts`, `recheckDueGame`, the game's ingest object in `functions/src/services/game-ingest.ts`, and the backfill), and keeps a stored value a fetch lacks at both game writes (`keepPlayerOfTheGame`). The sequence that breaks AC 5 without that: the rule settings are asked once, the next live poll's `fetchGame` answers without them, `storeGames` writes the fetched game whole, so the stored field disappears and each later poll that doesn't ask makes a new version for its absence (review-class checklist items 2 and 3). Whichever of S100 and S101 lands first generalizes S99's helper; the other reuses it. A game stored as final before this story never gets the field unless a path asks it again, the gap S99 accepted (#619): the ledger notes say whether this story accepts the same gap.
