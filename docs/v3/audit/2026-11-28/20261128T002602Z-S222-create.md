**Gap:** A finished item runs its tests three times in a row: its grader, then the finishing gate (`pnpm verify --all`, run by `scripts/audit.sh story` for a story and by the worker itself for a bug), then the commit hook (`.husky/pre-commit` → `scripts/pre-commit-tests.ts`), which reruns the tests the staged files reach. Because every finished item stages a changelog fragment and ledger fragments, the hook's trigger list sends it to the whole backlog tool suite (`@bt/scripts`' `test:fast`) on every such commit, although the gate has just run that suite, and more, on the same files. The speed review of 2026-11-27 (its second, measured pass) timed commits at 2–5 minutes, and for a small fix the gate, the commit and the waits around them were 23 of B642's 29 minutes. The owner, 2026-11-28, asked "Should I create the speed review's tooling stories T1–T7 in the backlog?": *"Yes, all seven"*; this is T1.

**Impact:** Before S222, committing a finished story or bug reran tests that had passed a minute earlier on exactly the same files, adding minutes to every item. After S222, a commit made right after a passing finishing gate skips that rerun and takes seconds, and any other commit is tested as before.

**Acceptance criteria** (checks `scripts/verify-S222.sh` performs)

1. **A passing finishing gate leaves a stamp of what it checked.** When `pnpm verify` runs the full graph (`--all` or `--full` / `BT_VERIFY_FULL=1`) and exits 0, it writes a stamp holding a content hash of the working tree it checked (every tracked and untracked, not ignored, file: its path, mode and content, so an edit, an added file and a deleted file each change it), the mode it ran in, and the time. The stamp lives in the worktree's own git directory (`git rev-parse --git-dir`), never in a tracked or shared file, so one worktree's stamp never reaches another. A narrowed `pnpm verify` (no `--all` or `--full`) and a failed gate never write one, and a failed gate removes any stamp already there. Unit tests in the `@bt/scripts` unit cover each of these.
2. **The commit hook skips its tests only on the stamped tree.** `scripts/pre-commit-tests.ts` computes the same hash (one function, ADR-025, shared with AC 1) and skips its test run, printing one line that says it skipped and which stamp it matched, when the working tree matches the stamp. The only difference it allows is ledger fragments under `docs/v3/audit/` that `scripts/audit.sh` added after the gate for the item the branch is named for (`story/S<N>`, `bug/B<N>`; the paths `isOwnRecord` in `scripts/backlog-vault/claims.ts` names for that ID; added files only, never a changed or deleted one, and on any other branch none). Any other difference, including a changed own record, a changed `changelog.d/` fragment or a frame note the hook's own canonicalizing step rewrote, runs the tests exactly as today. `BT_SKIP_PRECOMMIT_TESTS=1` keeps its meaning. Unit tests cover: the same tree skips; one changed byte in a tracked file runs; an added untracked file runs; a deleted file runs; only the item's own added ledger fragment skips; a changed own fragment runs; no stamp runs; a stamp from a narrowed run is never written, so it runs.
3. **The finished item's last files come before its gate.** A bug's `changelog.d/B<N>.md` is written before its finishing gate, not after it: `run-backlog`'s bug-worker brief (`.claude/skills/run-backlog/SKILL.md`, step 3) and `.claude/agents/bug-worker.md` put the fragment before `pnpm verify --all`, so the commit that follows matches the stamp. (A story's changelog fragment and `**Baseline:**` line already precede `audit.sh story`.) Checked by the grader reading both files' order.
4. **Lint and the other hook steps still run.** The skip covers only the test step: `lint-staged` and the backlog notes' `cli.ts pre-commit` step in `.husky/pre-commit` run on every commit as before. Grader: reads `.husky/pre-commit`.
5. **Measured.** The story's finishing commit adds a `**Measured:**` note (`scripts/audit.sh edit`) with the time of a finished item's commit before this story (the hook running its tests) and after it (the skip), on the same machine. Grader: the note exists with both times.
6. **Comments are true** (ADR-025): the hook's header comment and the stamp's writer say what is hashed, what difference is allowed and why the skip is safe (the full graph has just run every test the hook would select, on the same files).
7. Files outside the fence are untouched (`story_own_changed_files`); S222's **Status** is `done`: its snapshot records `done`, the status it ships with, written by `audit.sh story` (`story_snapshot_status`).
