**Gap:** `@bt/scripts#test` holds two kinds of test in one task: the law tests that read the product tree (ADR-030 rule 4: law P8's `verify-chain.test.ts`, P11's `ci-law.test.ts`, `laws.test.ts` and the build-graph tests behind laws L14–L17, among others) and the backlog tool's own tests (the ledger, text records, claims, run journal and debt scripts), which mostly read their own code and temporary repositories. Because the one task must declare everything either kind reads, its inputs in `turbo.json` include `docs/**`, `changelog.d/**`, `releases/**` and `functions/src/**`, so nearly every story or bug reruns all of it: in the speed review of 2026-11-27 (its second, measured pass) it was 51 files and 927 tests taking 219–411 s, the floor of every gate, and one file, `scripts/backlog-vault/review-debt.test.ts`, was 152 s of a 189 s run. The commit hook (`scripts/pre-commit-tests.ts`) runs the same suite whenever a changelog or ledger fragment is staged. Splitting it changes the inputs that laws L16 and L17 test, ADR-030 rule 4, and the nine rows of `docs/v3/LAWS.md` that name `@bt/scripts#test` as their enforcing task (L12–L18, P8, P11 at this story's writing), so the split is the owner's decision before anything is built. The owner, 2026-11-28, asked "Should I create the speed review's tooling stories T1–T7 in the backlog?": *"Yes, all seven"*; this is T2.

**Impact:** Before S225, a change to the app, however small, waited minutes for the backlog tool's own tests, which it could not affect. After S225, those tests run only when the tool or the files they read change, and the checks that guard the product's rules still run whenever a change reaches what they read.

**Source:** Feature: Fast PR checks
