**Gap:** In a `/run-backlog` run, a barrier item runs alone: nothing else starts while it is in flight, and it merges before the next wave (run-backlog step 3.1). An item is a barrier when its fence reaches a path `is_reviewer_path` (`scripts/claude-review/plan-review.py`) lists, which includes every `*.config.*` and `tsconfig*.json` at any depth and the root `package.json`; `isBarrierPath` (`scripts/backlog-vault/claims.ts`) excepts only a product package's own `vitest.config.ts`, `package.json` and `tsconfig.json` (`PACKAGE_OWN_CONFIG`, owner, 2026-11-22: "Don't count them (Recommended)"). So S151 ran alone for `web/vite.config.ts` and `web/tsconfig.sw.json`, files only `web` builds with, and S174 ran alone for one script line it added to the root `package.json`. The speed review of 2026-11-27 counted the next three items of that run all running at an effective concurrency of 1 for reasons like these. Worktrees already isolate such edits, and CI checks each pull request's merge result. The owner, 2026-11-28, asked "Should I create the speed review's tooling stories T1–T7 in the backlog?": *"Yes, all seven"*; this is T4.

**Impact:** Before S224, a story that only touched its own package's build settings, or added one command to the repository's list, held up every other story in a run until it merged. After S224, such stories run beside the others, and only changes to shared machinery still run alone.
