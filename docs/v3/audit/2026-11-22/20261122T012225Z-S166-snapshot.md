**Gap:** Two faults in the backlog scripts, both found while building S164 and raised by the 2026-11-21 backlog review.
- **The "run directly" check (issue #299).** Eight scripts under `scripts/backlog-vault/` (at this story's writing) each carry their own copy of the check that decides whether the file was started as a command or imported: `if (process.argv[1] && resolve(process.argv[1]) === fileURLToPath(import.meta.url))` (`claims.ts:935`, `github.ts:1516`, `search.ts:945`, `text-records.ts:717`, `in-flight.ts:62`, `areas.ts:262`, `triage.ts:86`, `migrate.ts:787`). Node gives `import.meta.url` the file's real path but leaves `process.argv[1]` as typed, so when the path goes through a symlink (on macOS every temp path does: `/var` is a link to `/private/var`) the two never match, `main` never runs, and the script exits 0 having printed and done nothing. Today's invocations use relative paths from the checkout, so nothing breaks yet, but `claims.ts claim` or `review-edits` run that way would report success having claimed or checked nothing.
- **The issue sync's extra reads.** On an incremental `pnpm backlog:sync`, `syncIssues` (`github.ts:522-539`) reads every open backlog issue the `since` listing didn't return, one request each (about 45 at today's size, and growing with the backlog), only to notice an issue that was deleted or transferred. A listing of the open issues (about 2 pages of 100) answers the same question.

**Impact:** Before S166, a backlog script started through a linked or temporary folder quietly did nothing and still reported success, and every quick refresh of the local copy of the issues asked GitHub about each open story one at a time. S166 impact: the scripts behave the same however they are started, and a quick refresh takes a few requests, one more for every hundred open issues and pull requests, instead of one for each open story.

**Baseline:** **S166** landed: the nine backlog scripts that compared paths to decide whether they were started as a command (`claims.ts`, `github.ts`, `search.ts`, `text-records.ts`, `in-flight.ts`, `areas.ts`, `triage.ts`, `migrate.ts`, `runs.ts`; `changelog.ts` and `design-reference.ts` use `import.meta.main`, which already resolves symlinks) do it through one shared check, `isRunDirectly` in `scripts/backlog-vault/run-directly.ts`, which compares real paths, so a script started through a symlinked or temporary folder runs instead of exiting 0 having done nothing (issue #299). An incremental `pnpm backlog:sync` (`syncIssues`, `scripts/backlog-vault/github.ts`) lists the open issues (`listOpenIssues`, sharing `listRawIssues`' pager) before the `since` listing and drops a cached open backlog issue missing from both and from a second open listing, read after the `since` listing only when there is such a candidate (so a page shift in the first open listing never drops an issue), with no per-issue request (`isHere` removed); an open issue the cache lacks is added back from the newest open listing, and an incremental sync prunes a `dropped` entry whose issue is in the cache again; a full sync lists and keeps the `dropped` list as before.
