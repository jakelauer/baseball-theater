**Gap:** Two scripts outside `scripts/backlog-vault/` still decide whether they were started as a command by comparing two spellings of their own path, which differ when the path goes through a symlink (on macOS every temporary folder does: `/var` links to `/private/var`). Node gives `import.meta.url` and `import.meta.filename` the file's real path but leaves `process.argv[1]` as typed, so started that way the check is false, `main` never runs, and the script exits 0 having done nothing:
- `e2e/select-specs.ts:192` (`if (import.meta.filename === process.argv[1]) main(...)`): the pull request check's browser-spec selection (S152). An empty answer from it reads as "no browser specs to run", so a run through a linked path would skip them silently. CI on Linux uses no symlinked path today, so nothing breaks yet.
- `web/src/api/codegen.ts:51` (`if (process.argv[1] === fileURLToPath(import.meta.url))`): `pnpm --filter web api:types` from a symlinked checkout exits 0 and writes no types.

S166 fixed the same fault in the backlog scripts (issue #299) and left these two outside its fence (its note names `select-specs.ts:192`); issue #315 records them.

**Impact:** Before S169, the pull request check's browser-test picker and the web app's API type generator quietly did nothing, and still reported success, when started through a linked folder. S169 impact: both run the same however they are started, so the picker can never skip the browser tests by accident and the generator always writes the types.

**Baseline:** The pull request check's browser-spec picker (`e2e/select-specs.ts`) and the web app's API type generator (`web/src/api/codegen.ts`, `pnpm --filter @bt/web api:types`) now decide whether they were started as a command with `import.meta.main`, which resolves symlinks, instead of comparing `process.argv[1]` with their own path; each has an end-to-end test that starts it through a symlinked folder (`e2e/select-specs.test.ts`, `web/src/api/codegen.test.ts`) (issue #315). `tools/comments-stale/comments-stale.js` still compares `process.argv[1]` with its own URL, outside S169's fence.
