**Body**

<!-- bt-body:begin -->
**Gap:** B81 (#81) made BT treat a suspended game (MLB `T`/`U`) as live, so its Live room shows the play so far and ingest keeps polling it for 6 hours, and an in-game delay (MLB `I`, e.g. `IR` "Delayed: Rain") already showed as live. But the UI can't tell either from a game being played: the game top bar (`GameTopBar`, `web/src/components/game/GameTopBar.tsx`) shows the same green "● LIVE" (`LiveIndicator`, `web/src/components/game/LiveIndicator.tsx`), the scoreboard row (`ScoreboardModule`, `web/src/components/scoreboard/ScoreboardModule.tsx`) shows the same green inning, and a start delayed before first pitch (MLB `P`, "Delayed Start: Rain") reads as a plain scheduled game. S157 drew the marker that says so and the owner ratified it (game-shell A7, `docs/v3/visual/game-shell/amendments/A7.md`, 2026-11-22: *"Ratify A7"*); nothing builds it.

**Impact:** Before S170, a suspended or rain-delayed game looked exactly like one being played, and a game whose start was delayed looked like it would start on time. S170 impact: the game page and the scoreboard say "Delayed · Rain", "Delayed start · Rain" or "Suspended · Rain" in gold, so a fan sees at a glance that the game has stopped, or hasn't started, and why.

**Source:** Feature: Game status marker

**Design:** S157 — build to the approved frames (game-shell A7). This story may only move to `doing` once every design story named here is `done` (rule 18; `pnpm backlog:check` enforces it).

**Depends on:** **S81** (design capture). **Prefer after:** S148 (it rewrites `LiveIndicator`'s comment; this story reshapes the same component).

**Scope files:** `web/src/`, `web/vitest.config.ts`, `packages/domain/`, `e2e/design/`, `docs/v3/design-checks/`, `docs/v3/backlog/`

**What already exists (B81):** `STATUS_KINDS` and `normalizeStatusCode` (`packages/domain/src/window.ts`) sort every MLB `codedGameState` into pregame, live, suspended, final, postponed and unknown; `isSuspendedStatus` and `isLiveStatus` say whether a game is suspended or looks live (`I`, `M`, `N`, `T`, `U`); `gamePhase` (`packages/domain/src/game-phase.ts`) already puts a suspended or delayed game in the live phase, so its Live tab shows. Every game and schedule status carries MLB's `detailedState` (`GameSnapshot.status`, `packages/domain/src/types.ts`), which is where a delay's or suspension's reason ("Delayed: Rain", "Suspended: Rain", "Delayed Start: Rain") comes from: `codedGameState` alone can't tell a rain delay (`I`) from play in progress (`I`), or a delayed start (`P`) from warm-up (`P`).
