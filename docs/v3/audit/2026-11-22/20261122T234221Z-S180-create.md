**Acceptance criteria** (checks `scripts/verify-S180.sh` performs)

1. **Built from the day's packages.** The digest's facts are S177's day-digest fact pack over the stored game packages of one MLB day (`officialDate`), never a fresh walk of every raw play (ADR-011); each fact carries its `gamePk`.
2. **Written once the day is settled.** One domain function, `daySettled(scheduleDay, packages)`, is true when every game of the day is final with a package, or postponed, cancelled or suspended (none of which is ever final; a suspended game resumes another day); a day with a game still live, delayed or not started is not settled (table test, including a day of only postponed games, which has nothing to write and writes nothing, and MLB's today while a game is live). The tick enqueues the digest job once per settled day, keyed by the date and its packages' versions; a package rebuilt later (a new version) writes a new digest that replaces the served one (ADR-022; test).
3. **Each item names its game, and is checked against it.** `AiDayDigest` holds a `headline` and 3–8 `items`, each with its `gamePk` and text; it comes from S176's `writeVerified` (full loop: rules checker, fact-checker agent, up to two revisions), and the rules checker checks each item against its own game's facts, so a name or number from another game is an error (a test drafts an item that mixes two games' facts and sees it flagged). A digest that still fails is not published.
4. **Served.** `GET /api/v1/digest/written?date=YYYY-MM-DD` answers `AiOutputResponse<AiDayDigest>` to whom `canReadAiOutput` allows, `null` for a day not settled or not written; it answers 400 for a malformed date as `GET /api/v1/digest` does; in `ApiRoutes` (law L4) and the OpenAPI spec (additive, `pnpm api:breaking` exits 0, `web/src/api/generated/` regenerated), cached by `cacheLifetimeMs` (ADR-021). The existing `GET /api/v1/digest` answer is unchanged (its tests pass untouched).
5. S180's **Status** is `done`: its snapshot records `done`, the status it ships with, written by `audit.sh story` (`story_snapshot_status`).
