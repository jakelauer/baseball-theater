**Gap:** FEATURES' Impact curation asks, per game, for clips that are *"**notable** even if low leverage (bizarre play, milestone, filthy pitch, Statcast outlier)"*, an "Also interesting" list beside the impact order, and nothing finds them: BT ranks clips only by how much their play swung the game (S98). The owner put "also interesting" clips in the backlog (owner, 2026-11-22: *"1, 2, 3, 4, 5, 6, 7, 8 should go into the backlog."*) as an API feature for now (*"Oh ok, fair. I would say we can just make these API features for now."*), with no fine-tune (*"No fine-tune (Recommended)"*). The research (`docs/v3/AI-RESEARCH-2026-11.md` §5 row 7) uses rules and statistics: how far a pitch or batted ball sits out in the league's own distribution, rare event types, and in-game accomplishments.

**Impact:** Before S183, a game's clips were ordered only by how much each play mattered to the result, so a 103-mph fastball or a bizarre play in a blowout sank to the bottom. S183 impact: for every game BT picks the few clips that are remarkable for their own sake, each with a plain reason ("hardest-hit ball in the league this season: 118.6 mph"), from rules and the league's own numbers, with no AI call and no AI cost.

**Acceptance criteria** (checks `scripts/verify-S183.sh` performs)

1. **The league's own numbers.** `pnpm ai:league-distributions --season <year>` computes, from the games BT stores for that season, percentile cut points (the 1st, 5th, 95th, 99th and 99.9th) for pitch speed, spin rate, exit velocity, launch angle and hit distance, and, where the stored games hold them (Savant's fields, S103), expected batting average and catch probability; it writes them to a committed, versioned file the Worker bundles (`functions/src/generated/`, as S132 bundles release notes), and a test checks the bundled file parses and names its season and version. A field with too few values in the season (fewer than 1,000) gets no cut points and no picks.
2. **Rules pick the clips, with a reason.** One pure domain function, `alsoInterestingClips(game, distributions)`, picks a game's clips of plays that are: past the 99th percentile (or below the 1st) on any field of AC 1; a rare event type (at least: a triple play, a steal of home, an inside-the-park home run, a position player pitching, an immaculate inning); or an accomplishment from S178's rules. Each pick carries a reason code and a reason line filled from a fixed template with the play's own value (no model), and clips already in the game's top 5 by impact are left out, since they are already first. At most 3 per game, by how rare the reason is. Table tests on invented plays for each reason, a clip with no play (never picked), and a game with none.
3. **Tuned on past games.** `pnpm ai:also-interesting-report --season <year>` runs the rule over every stored game of a season and writes `docs/v3/ai-eval/also-interesting-<year>.md`: picks per game (median, share of games with none) and the count by reason; the committed report shows the thresholds give a median of 1–3 picks a game. The story records which season it was tuned on.
4. **Served.** `GET /api/v1/games/:gamePk/also-interesting` answers `{ clips: AlsoInterestingClip[] }` (no AI was used, so it is not an `AiOutputResponse` and needs no `canReadAiOutput`), in `ApiRoutes` (law L4) and the OpenAPI spec (additive, `pnpm api:breaking` exits 0, `web/src/api/generated/` regenerated), cached by `cacheLifetimeMs` (ADR-021). Route tests: a game with picks, one with none, an unknown game (404).
5. S183's **Status** is `done`: its snapshot records `done`, the status it ships with, written by `audit.sh story` (`story_snapshot_status`).
