The owner's brief (`docs/v3/PITCH-MODEL-BRIEF.md`) makes phase 2 a minimal end-to-end pipeline (current state plus one short window of recent pitches, one target: the next pitch's type) and phase 3 a reliable evaluation (later, unseen games; log loss and calibration, not only top-1 accuracy; league-wide and pitcher-specific baselines; preserved datasets and configurations). **Impact:** Before S186, BT had training examples but no model and no way to tell a good one from a bad one. S186 impact: BT trains a first model that gives the odds of each pitch type before every pitch, and measures it honestly on games it never saw against simple guesses ("what this pitcher usually throws in this count"), so every later improvement can be proven, not assumed.

**Acceptance criteria** (checks `scripts/verify-S186.sh` performs)

1. **Whole games, in time order, and a frozen final period.** One split definition in `ml/` assigns every game wholly to a training, a development and a final period by date (the final period the latest, set in a committed config); a test shows no game in two splits and every development and final game later than every training game. The final period's game ids are committed with a hash, and `ml/`'s evaluation refuses to read them without `--final`; every `--final` run is logged in `docs/v3/pitch-model/final-period-log.md` (the brief's §12: a final, untouched evaluation period).
2. **Baselines.** Computed only from data before each prediction (test: a pitch's baseline odds don't change when later games are added): the league's pitch-type mix, the league's mix in that count, the pitcher's own mix, and the pitcher's mix in that count backing off to his overall mix and then the league's when he has few pitches. Each is a model the evaluation runs like any other.
3. **The raw-sequence baseline model.** A first learned model (a gradient-boosted tree model, the brief's §10 A) trained on S90's examples: the current state plus one window of the preceding ordered pitches with their raw measurements, encoded (categories, scaling) but with no baseball statistics computed in advance. It is kept as the standing baseline every later phase reports beside (the brief's §8).
4. **Measured as probabilities.** The evaluation reports, on the development period and per season: log loss (the primary measure), expected calibration error and a reliability table per pitch type, Brier score, and top-1 accuracy (secondary), for every baseline and model side by side. Tests compute each measure on small hand-worked examples.
5. **Repeatable.** Each experiment is a committed config (data range, window, encoding, model and its settings, seed, hardware) and a committed results file under `docs/v3/pitch-model/experiments/`; re-running a config on the same data reproduces its log loss to within 1e-4 (test on the committed sample).
6. **The phase's report.** `docs/v3/pitch-model/phases-2-3.md` says whether the model beats the best baseline (the pitcher's mix in that count) on development log loss and calibration, by how much, and per season, and ends with one `--final` run of the chosen model and the baselines.
7. **Within the owner's budget.** Every paid run is logged in `docs/v3/pitch-model/spend.md` (hardware, wall time, cost); `ml/`'s run command refuses a run whose estimated cost passes what remains of the approved budget, and a phase that needs more asks the owner first, the approval quoted in that file (test of the refusal with a fake price).
8. S186's **Status** is `done`: its snapshot records `done`, the status it ships with, written by `audit.sh story` (`story_snapshot_status`).

**The brief's guiding rules hold in every phase** (`docs/v3/PITCH-MODEL-BRIEF.md` §8, §12, §13): the raw-sequence baseline of S186 is kept and every result is reported beside it; engineered features enter only as measured experiments; every split holds out whole games in time order, and the frozen final period is read only as §12 says; and no paid run passes the training budget the owner approved (S90's `**Training budget:**` line, or a later approval quoted in `docs/v3/pitch-model/spend.md`).
