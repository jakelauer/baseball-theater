**Gap:** ADR-023: anything already viewed stays readable offline, marked with its age; on open (and on any background wake) today's scoreboard and favorite teams' games are prefetched; Periodic Background Sync where the browser offers it; offline copies obey Hide Scores exactly like live views; the service worker stores the latest copy it was given and never decides freshness (ADR-014 rule 3). **Impact:** Before S74, losing signal meant a blank app. S74 impact: games and scoreboards you have already opened still read offline, marked with how old they are, today's games and your teams' games are fetched ahead, and Hide Scores still applies.

**Source:** Feature: PWA / installability

**Baseline:** The service worker is BT's own source, `web/src/pwa/sw.ts` (vite-plugin-pwa's `injectManifest`), under law L1's lint: every cache it keeps comes from `web/src/storage/workerCaches.ts` and is labeled in `web/src/storage/storage.ts`. It keeps the last 200 answer to every `/api/v1/*` GET except `/api/v1/me` and below, network first, in the `bt-api-v1` cache (`API_CACHE`, labeled personal: sign-out and account deletion delete it through `clearPersonalData()`, as ADR-028's Browser row lists offline caches; the pattern `RUNTIME_CACHED` in `web/src/pwa/options.ts`), each answer keyed by its URL alone so no `Authorization` header is stored, with no expiry or timeout, so the worker never decides freshness; queries run `offlineFirst` so they reach it offline, except the calendar's months, which pause offline as S194 has them. On open and on waking (`web/src/pwa/prefetch.ts`), today's schedule is fetched ahead, and a signed-in user's favorite teams' games too; Periodic Background Sync (handled in `sw.ts`) registers only where the browser offers it. Design matched by the owner 2026-11-23 (six captures in `docs/v3/design-checks/S74/`).
