**Gap:** BT orders a game's videos by its own rule (Impact curation Phase A, S98: `rankHighlightsByImpact` in `packages/domain/src/impact.ts`, by the win probability each clip's play added), and FEATURES' Phase B is a model that ranks them better. A ranking model learns from what fans actually watch, and BT records nothing about that: no count of which clips are started or watched to the end. The research the owner read on 2026-11-22 (`docs/v3/AI-RESEARCH-2026-11.md`, §5 row 6 and §6 step 3) says to start counting now, so that a ranking model can be trained after about a season (S185). The owner put the eight AI ideas in the backlog (owner, 2026-11-22: *"1, 2, 3, 4, 5, 6, 7, 8 should go into the backlog."*), model-assisted highlight ranking among them, as API features for now (*"Oh ok, fair. I would say we can just make these API features for now."*).

**Impact:** Before S174, BT had no idea which videos fans actually play or finish. S174 impact: BT keeps an anonymous daily count, per video, of how often it was started and how often it was watched to the end, with nothing about who watched, so a later model can learn which clips fans want to see first.

**Baseline:** BT counts, anonymously, which videos fans start and finish. The Privacy policy (`web/src/pages/legal/privacy.md`) carries the owner's approved sentence under its own heading, Video counts. `packages/domain/src/clip-views.ts` holds the rules: `ClipViewEvent`, `clipCompleted` (90% of a known length, `CLIP_COMPLETE_SHARE`), `clipShownPosition`, `clipViewDay` (the UTC day) and `parseClipViewRequest`. `POST /api/v1/clips/:mediaId/views` (`ClipViewRequest` body; the route table's first `NoContentResponse`, a 204 in the spec) adds one to a `clip_engagement` row keyed by clip, game, UTC day, event and place in the game's ranked Videos list, with one atomic `INSERT … ON CONFLICT … DO UPDATE SET count = count + 1` (`PostgresClipEngagementRepository`, migration `0010_clip_engagement`; `InMemoryClipEngagementRepository` its double, one contract for both); it answers 403 (`cross_site`) for a request that isn't from BT's own page (`Sec-Fetch-Site` must be `same-origin`, or, without it, `Origin` the request's own, so counts from a LAN device under `pnpm dev` are refused), 400 for a bad body (extra keys included, as the spec's bounds and `additionalProperties: false` say) and 404 for a clip not among the game's stored highlights (`GameRepository.hasHighlight`, which never loads the game's document), sends no CORS headers, reads no cookie or session and logs nothing. The manifest labels both repositories and the table `none`, and the baseball copy never copies the table. Only the Videos room's dialog sends views (`countViews` through `PlayerHost`, `PlayerDialog` and `PlayerProvider` to `VideoPlayer`), once per opening, a finish only after the opening's counted start and at its shown position, through `sendClipView` (`web/src/api/clipViews.ts`: `navigator.sendBeacon`, else `fetch` with `keepalive`, failures dropped); `pnpm clips:engagement-export --from --to [--out]` writes a range's rows as JSON lines for S185.

4. **The route.** `POST /api/v1/clips/:mediaId/views` with body `{ gamePk, event, shownPosition }` (an integer 0–100; 400 otherwise) answers 204 and counts one; it is in `ApiRoutes` (law L4) and the OpenAPI spec (`pnpm api:spec`, additive, `pnpm api:breaking` exits 0), and `web/src/api/generated/` is regenerated. It answers 400 for an event that isn't `start` or `complete` or a body that isn't that shape, and 404 when `mediaId` is not one of that game's stored highlights (nothing is counted either way), so a caller can't create rows for clips BT doesn't have. It reads no cookie and no session.
5. **Nothing about the viewer.** The table has no column for a user, session, IP address, device, user agent or a time finer than the day (a schema test lists its columns); the handler logs no request identifiers (law P5); the classification manifest (`functions/src/services/data-classification.ts`) labels the repository `none` with its why ("anonymous daily counts per clip; nothing about who watched"), so law L3's test passes.
6. **The Videos room's player sends it.** Only clips played from a game's Videos room (its ranked list) are counted, so every count's position means the same list; Search's, the day digest's and the stage players send nothing (a test shows they don't). The player the Videos room opens (`web/src/components/videos/VideoPlayer.tsx` today) sends `start` the first time a clip plays after it is opened with the clip's shown position, and `complete` once per opening when the element fires `ended` or `clipCompleted(position, duration)` is true (a clip whose duration is 0 or `NaN` completes only by `ended`), through one function in `web/src/api/` that uses `navigator.sendBeacon` and falls back to `fetch` with `keepalive`; a failed send is dropped silently (no retry, nothing shown).
