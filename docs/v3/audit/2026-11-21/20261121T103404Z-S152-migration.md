**Body**

**Gap:** Every pull request's checks rebuild and retest everything from scratch, and the slowest two jobs set the wait (measured on six pull request runs, 2026-11-19): `design-specs` takes 5–9 minutes, about 4 of them reinstalling the Playwright browser (`playwright install --with-deps chromium`, 247 s in one run), which `flows` repeats; `verify` takes about 7.5 minutes, one 408 s step (`pnpm verify`) of which the `functions` package's tests with coverage are about 5 minutes, run in full even when a pull request touches only `web/` or docs. Nothing is cached between runs but pnpm's package store. The owner asked for it (owner, 2026-11-19: *"Can we get scoped build caching somehow so we can avoid a full rebuild for PR checks"*), and chose, offered four speed-ups, all four: a prebuilt browser image, skipping unchanged packages, splitting the functions tests, and ESLint and tsc caches. The aim is to build only what a change touches (owner, same day: *"The point would be to only build the stuff that changes"*): asked whether `stage` should rerun everything after a merge, *"Stage reruns everything (Recommended)"*; asked whether the browser jobs should run only the specs a change could affect, *"Yes, scope them too"*.

**Impact:** Before S152, every pull request waited about 9 minutes for its checks, however small the change. S152 impact: a change to one part of the app reuses the passing results of the parts it doesn't touch, the browser is kept between runs instead of reinstalled, and the slowest tests run in parallel, so most pull requests finish their checks in a few minutes.
